- `server` CLAUDE: "Pre-rasterize team logos to PNG; serve via /logo?size=1x|2x
  The 960x640 vector logos were being downscaled by the browser to
  ~48px in a single pass. That's fine for the simple marks but leaves
  detailed historical crests (fine outlines, pinstripes, small text)
  looking scratchy, most visibly in the standings chart's `<image>`
  element on retina displays.
  Add a small Node build step (npm run build:logos, sharp + svgo):
  - SVGO-optimizes every SVG in app/logos/ in place (159 of 165 shrunk,
  ~33 KiB saved)
  - rasterizes each to square NAME@1x.png (64px) and NAME@2x.png
  (128px) via sharp's lanczos3 downsample, transparent-letterboxed
  to match how the SVG's own preserveAspectRatio centers the 3:2
  artwork
  Extend GET /logo with an optional ?size=1x|2x: serves the matching
  PNG when present, otherwise falls back to the SVG (unknown/missing
  size, or a size passed with no generated PNG). Path-traversal guard
  covers the derived PNG filename the same way it covers the SVG.
  node_modules/ and package-lock.json are gitignored; re-run
  `npm run build:logos` whenever a logo in app/logos/ changes."
